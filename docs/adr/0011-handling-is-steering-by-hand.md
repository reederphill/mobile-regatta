# Handling is steering by hand; the autohelm is a boat class setting

The autohelm of ADR 0007 becomes a value in the boat class file, `steering.autohelm.holdsWhenCentred` (schema 4, ADR 0004), tuned for every boat at once, players and bots alike. On (true, and every file that leaves it out), a centred rudder is ADR 0007's autohelm, exactly as before. Off, a centred rudder is a centred rudder: she sails straight on her heading, the autohelm never engages on centring and never snaps to the groove, and every shift and puff is hers to steer through. The tack/gybe tap still hands her to the autohelm, which sails the turn onto the groove on the new tack and, past the boom, lets go with the rudder centred once she is within the class's `handBackDegrees` (3°) of it, so she doesn't stall just past head to wind. Settled in [#426](https://github.com/reederphill/mobile-regatta/issues/426) (Q10, 2026-10-09) and built in [#434](https://github.com/reederphill/mobile-regatta/issues/434), overriding part of ADR 0007 and [#219](https://github.com/reederphill/mobile-regatta/issues/219). The default class has it off for every boat: skiff@7 from [#437](https://github.com/reederphill/mobile-regatta/issues/437) (2026-10-10, simulation revision 36), skiff@8 from [#461](https://github.com/reederphill/mobile-regatta/issues/461) (revision 37). Only the older classes and old logs have it on. It is no player setting; the Debug tuning menu switches it for a class ([#436](https://github.com/reederphill/mobile-regatta/issues/436)), and the owner keeps it as a vestigial class value in case a beginner mode is added (2026-10-09).

We did this because the autohelm made the legs mindless: holding the groove through every puff and shift left nothing to do between decisions. #426 set out to add boat handling as a second skill axis beside tactics. The handling mechanics tried on the throwaway `proto-handling` branch (an overpowered state with Ease and wipeouts; Ease as a sheet dial with a fast heel band) were either a tapping game to survive gusts or too much to work while steering. The `proto-tiller` branch, main's sailing model with only the player's autohelm turned off, played "much better". Steering through the wind at your boat is the handling skill.

## Considered options

- **Keep the autohelm and add a gust mechanic (heel, overpowered, depower with Ease, wipeout):** rejected after playtest. Ease is a separate button, so depowering fought steering.
- **Ease as a sheet dial with a fast heel band and rounding up:** rejected after playtest as too much.
- **Flat, groove and overpowered stages shown as tilt, steered out of:** dropped before it was built (2026-10-09).
- **A per-player setting, bots keeping the autohelm:** rejected (owner, 2026-10-09). Bots and players sail the same model, and a per-player choice would mean two input models in one race.
- **A race option or an unlogged app flag (the prototype's):** rejected. Everything the simulation reads about a boat is in her class file (ADR 0004), so the setting is logged by the file's ref, the server sails the same file, and the tuning panel tunes it like any other value: a tuned copy writes a number, so the file takes 0 or 1 as well as a JSON bool.
- **Autohelm off as a class value (chosen):** the smallest change that gives the legs something to do, and it reuses the polar, vane, groove and tap as they are.

## Consequences

- This reverses ADR 0007's rejection of a heading-hold option. There is still one input model per race, as ADR 0007 wanted: every boat sails the race's class.
- A new simulation version (ADR 0002). Revision 35 ([#434](https://github.com/reederphill/mobile-regatta/issues/434)) moved nothing on the default class; the default switches (#437, revision 36; #461, revision 37) moved bot tracks, the REGATTABOTS replay digest and the render fixtures, which follow the default class.
- With the autohelm on, bots sail by centring on an aim and leaving it to the autohelm. With it off, the default, they hold the aim themselves (`BotHelm` in RegattaBots): the angle the autohelm would have taken on centring, turned into a held rudder each decision with the autohelm's own rudder law, so a bot with a perfect hand sails the autohelm's track to within a fraction of a hull length. Two known differences: a held rudder inside the autohelm's dead band (about 0.5° of error at the class's gain) is centred, so she can sit that far off her aim; and under a backwind header she steers by the headed angle she sees, where the race's autohelm holds a groove's heading through it (#377). Bots steer like sailors of their tier ([#435](https://github.com/reederphill/mobile-regatta/issues/435), [#443](https://github.com/reederphill/mobile-regatta/issues/443)): shift lag, wander and overshoot scale with a handling skill drawn apart from tactics skill, inside a per-tier band (Club 0.35–0.75 in `bot-tiers@3`), so a sharp tactician can have a sloppy helm.
- The escape simulation and course prediction read the setting: off, a centred rudder predicts a straight course. A player's centred rudder no longer follows a shift, but a bot holding its aim by hand (`BotHelm`) still does, through a held rudder (CONTEXT.md **Hold course**). The watchdog counts only centred-rudder calls, so with the autohelm off it doesn't see a bot's shift-following course change. [#228](https://github.com/reederphill/mobile-regatta/issues/228)'s shift-following case applies to players only with the autohelm on.
- Amended by [#458](https://github.com/reederphill/mobile-regatta/issues/458) (skiff@8, the default class since [#461](https://github.com/reederphill/mobile-regatta/issues/461), 2026-10-10): every tack, gybe and penalty turn is steered by hand, and the app has no Tack/Gybe button ([#460](https://github.com/reederphill/mobile-regatta/issues/460)). A class may also set `steering.autohelm.sailsTap` false, and then the tack/gybe tap is logged and does nothing else, so she tacks and gybes by hand; and with the rudder centred inside the no-go she falls off at `headToWindFallOffCentredDegreesPerSecond` until she has steerage (irons recovery), which a held rudder never triggers.
- The groove stays the target to steer to. With the autohelm off the vane locks to the groove tick when she sails within the lock angle of it and draws the pinch/foot arc from her own angle ([#436](https://github.com/reederphill/mobile-regatta/issues/436)).
- Handling is the second skill axis beside tactics, so ADR 0007's skill-gap consequence is a 2×2 gate, with its measurements ([#426](https://github.com/reederphill/mobile-regatta/issues/426)).
